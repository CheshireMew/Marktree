# Marktree 测试

## 日常检查

```powershell
npm test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-msvc
npm run test:cli
npm run check:windows-native
npm run check:android-rust
npm run check:android-native
```

Windows 原生开发验证使用 `npm run check:windows-native`。脚本在独立真实目录中启动两次 Tauri 开发进程：第一次让 Vue 工作区和真实 CodeMirror 打开文档、修改内容并请求关闭，由窗口关闭拦截刷盘；第二次从同一目录读回精确内容、确认编辑器已经渲染，再修改并关闭。每个阶段都由脚本直接比较最终磁盘字节，运行证据保留在脚本输出的目录中，不生成安装包。`npm run check:android-rust` 编译 Android `aarch64` Rust 链路，不生成 APK；脚本可使用 CI 提供的工具链，也会优先复用本机 `D:\Tools` 环境。

Android Debug 的原生界面与清单检查先通过 Tauri 移动端开发准备流程，把仓库内的 `marktree-android-bridge` 模块注册到生成工程；随后在 `src-tauri/gen/android` 运行 `:marktree-android-bridge:compileDebugKotlin`、`:app:compileArmDebugKotlin`、`:app:processArmDebugMainManifest`、`:app:compileUniversalDebugKotlin` 和 `:app:processUniversalDebugMainManifest`。脚本最后检查真实生成的 `SharePlugin.class`，并确认 Arm 与 Universal 最终合并清单都包含受支持的分享入口、主 Activity 和唯一 FileProvider。整个过程不会进入 APK 打包任务。

## 真实普通工作区测试

`src-tauri/src/workspace.rs` 和文档测试使用真实、没有 `.git` 的临时目录，验证普通文件夹可以直接打开，目录树包含文件与目录，Markdown 和纯文本能原样读取与保存，图片可读取，新建、保存、移动和回收由真实文件系统完成，且整个过程不产生 `WorkspaceChange`。源码保真测试把带 BOM、CRLF 和扩展语法的真实磁盘字节送入读取生产者，再经保存生产者落盘，最终直接比较磁盘字节，不在消费端重造输入。

`src-tauri/src/archive.rs` 把真实普通工作区导出为 ZIP，再导入到新的应用私有工作区，直接比较文件字节、空目录和配置，并确认 `.git` 与内部状态没有进入归档。恶意路径、重复项、体积超限、符号链接和任意层级的 `.git` 元数据必须在暂存目录提交前失败。`src-tauri/src/portability.rs` 使用真实普通目录和真实 Git 仓库消费系统分享载荷，验证文字确实新建文件或按选择进入当前文档，一般附件以原字节进入用户选择的目录并返回普通相对链接；成功后只删除对应的应用缓存传输目录，失败时保留输入供重试。缓存管理测试还覆盖路径边界、保留期和总量预算。普通工作区不产生变更清单，而 Git 工作区只产生对应路径的精确 `Upsert`。

`src-tauri/tests/cli_integration.rs` 启动真实 `marktree-cli` 进程。普通工作区测试从 CLI 标准输入写入并直接比较磁盘字节，再由另一次 CLI 读取；只读命令证明缺少状态目录时不会创建目录或锁文件，状态单元测试还让已经启动的只读视图读取后续写进程的新状态。Windows 上需要一致事务视图的桌面和 CLI 入口从第一次访问起共用按工作区身份命名的系统互斥量；搜索另以可取消时间点扫描、原子发布和消失文件容错验收。并发测试让两个进程同时写入同一 Git 工作区，证明共享状态保留两条精确变更；完整 Git 测试使用真实仓库和裸远端，由 CLI 写入、提交和推送，再让第二个克隆快进并通过 CLI 读取结果。测试专用 `test-local-remotes` feature 只允许本地裸远端进入该验收，正式构建仍只接受 HTTPS。

嵌套仓库测试会在普通父目录里建立多个真实 Git 子目录。父目录仍是普通工作区，子目录内容可见而 `.git` 隐藏；只有单独打开子目录时才生成 `GitCapability`。反向边界测试还会把普通工作区放进父 Git 仓库，逐一验证状态、分支、同步和 CLI 都拒绝借用父仓库。文件操作测试还会验证目标覆盖、符号链接逃逸与外部修改冲突不会破坏磁盘内容。

## 真实 Git 集成测试

`src-tauri/src/git/tests.rs` 的测试不 mock libgit2。测试会在临时目录中创建普通仓库、Worktree 和裸远程仓库，并验证：

- 工作区状态和结构化 diff 来自真实文件修改；
- 启用 Git 会先展示真实版本化文件的数量、大小和忽略摘要，再建立同时包含普通内容和隐藏工作区配置的本地基线提交；
- 同步事务只提交 Marktree 记录的精确 `Upsert` 和 `Delete` 路径，用户原有暂存内容和暂存删除在同步后仍留在索引中；
- 成功重试会清空完整的已记录变更清单，不遗留失效路径；
- 同步提交使用独立 index，进程在提交后退出并恢复时不会重复提交，也不会丢失用户原有暂存项；
- 文档经写入、提交和推送后，可被第二个真实克隆读取；普通工作区先保存的 `.marktree/config.json` 也会在启用 Git、推送后被第二个真实克隆读取；
- 远端提交经 fetch 和 pull 后，第二个克隆的工作区文件真实更新；
- Worktree 由 libgit2 创建并能读取同一文档；
- 分支创建、切换、脏工作区拒绝切换和删除都作用于真实仓库；
- 两个克隆制造文本、二进制和删除冲突后，可用的祖先、本机与远端内容都进入恢复区；
- 冲突记录跨重启恢复，选择本机、远端或合并内容后可继续变基和推送；
- stash 在应用前退出、应用后退出和恢复中遇到新外部写入的窗口都经过真实仓库验证；中止操作也能跨重启完成；
- 第三个真实克隆最终读到冲突处理后的内容。

`src-tauri/src/workspace_operation.rs` 在操作意图已保存、文件系统刚生效、目录副本只写入一个文件、阶段刚保存、基线刚提交和基线阶段刚保存等持久化边界注入进程停止。恢复测试使用真实文件与真实仓库，证明完整的操作暂存文件可在重启后发布，部分暂存不会暴露为最终文件，单文件写入最终只生成一个精确变更、目录移动的全部删除与新增路径一次出现、目录复制从真实执行计划补齐文件和空目录且只登记目标路径、Git 基线只创建一次。目录扫描与真实 Git 状态测试还证明事务暂存、备份和拒绝文件不会进入用户目录树或版本状态。测试会从实际应用数据日志中读取该写入的完成记录；前端组件测试再证明设置页能够显示同一日志合同，且合同没有正文或凭据字段。

同一测试模块还覆盖文件系统调用返回错误的两种真实结果：目标效果已完整落盘时命令返回恢复结果并只记录成功，完全未落盘时移除待处理意图并只记录失败，防止同一操作出现互相矛盾的终态。

`src-tauri/src/documents/tests.rs`、`tests/editor-source.spec.ts` 和组件测试使用包含 Frontmatter、表格、任务、脚注、公式、Mermaid、中文、UTF-8 BOM、CRLF、混合换行和未知扩展的语料，验证未编辑内容逐字节不变、局部编辑不改写无关换行、外部写入不会被覆盖、配置文件外部修改不会被覆盖、独占创建不会替换现有文档、损坏的同名资源会被实际修复、脚注可见且不改写源文本。结构化搜索测试由真实磁盘文件产生路径与正文命中，并核对目录、类型、修改时间筛选以及行号、列号和片段；扫描中消失的文件会被跳过，超大文件和总量预算测试验证生产者返回明确截断统计且不会无界读取。媒体预览测试从生产命令返回的受控资源路径读取并比较图片、PDF、音频和视频的真实磁盘字节；资源上传测试把真实分块写入临时文件，验证乱序拒绝、所属文档消失或被同路径替换时拒绝发布，以及最终工作区内容。`tests/upload-coordination.spec.ts` 验证移动等路径操作会等待上传，稳定占位符会保留上传期间的后续编辑；工作区根测试验证同一路径的并发打开只触发一次原生读取并只生成一个标签页。组件测试在真实 CodeMirror 缓冲区上执行表格、公式、相对文件链接、手机工具栏和个人片段插入，并检查片段版本化导入导出。路径状态测试让正式文档打开器按保存路径重新打开标签，同时验证移动后收藏与当前标签路径迁移、持久状态不含正文。导航、阅读、打印、搜索高亮、预览标签和 Android 目标选择都经过可见组件操作。保存协调器测试验证同一标签页的连续修订不会乱序落盘。三方合并测试同时覆盖互不重叠编辑、重叠冲突和空祖先，冲突组件测试会执行真实候选选择并检查最终提交内容。

Rust 的工作区视图测试使用真实 Git 仓库，确认目录条目标记和顶部状态来自同一份快照。运行时测试覆盖弱引用工作区锁回收、窗口隔离的搜索取消、完成后搜索记录释放和忘记工作区清理。IPC 生成检查同时验证命令登记、实际 Tauri 标记、可达 DTO、Serde 形状和生成文件漂移；Rust 序列化测试直接核对启动 DTO 与待恢复 Git 摘要的真实 JSON 字段和值。阻塞调度测试记录调用线程，证明同步原生工作离开 Tauri 异步执行线程。

## 视觉检查

先启动本地预览：

```powershell
npm run dev -- --host 127.0.0.1
```

再运行：

```powershell
npm run test:visual
```

检查会使用系统 Edge 的无头模式打开独立的普通工作区和 Git 工作区演示数据，验证亮色桌面、暗色紧凑桌面和暗色手机尺寸，确认前端真实启动、目录树可展开、命令中心按普通/Git 上下文显示能力并呈现搜索筛选、层级大纲和阅读入口可达、设置中的编辑偏好完整可滚动、手机表格/公式/附件工具可达、普通工作区主界面没有 Git 操作、启用入口只位于工作区设置、Git 高级功能只在面板中出现、没有页面错误、横向溢出或移动端 Git 复杂界面泄漏，并保存截图到忽略提交的 `test-results/`。
