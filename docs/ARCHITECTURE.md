# Marktree 架构

## 单一真源

仓库工作目录里的 Markdown 和资源文件是内容真源，Git 仓库是历史与跨设备同步的真源。前端只持有每个 Worktree 当前会话的临时编辑缓冲区；切换仓库或 Worktree 不会复用另一棵工作目录的标签页、保存队列或磁盘版本。

文档和 `.marktree/config.json` 都采用版本化保存。Rust 读取时返回 SHA-256 与“文件是否不存在”，写入前精确比较调用方看到的版本和当前磁盘版本；发生外部修改、删除或重新创建时返回结构化冲突，不覆盖磁盘。新文档使用独占创建，原子写入只替换已通过版本检查的目标。图片按内容哈希命名，读取和写入都有大小上限；同名内容损坏时会修复实际文件，不能用文件名存在冒充写入成功。

本地应用状态位于 Tauri 应用数据目录，只记录：

- 最近打开的仓库与文件；
- 仓库对应的系统凭据条目 ID；
- Marktree 保存或加入过、等待同步的相对路径及其代次；
- 可恢复的 Git 操作阶段；
- Git 冲突的祖先、本机、远端恢复副本。

正文没有数据库、缓存副本或其他内容镜像。主题等纯界面偏好可以留在前端本地存储，但不能承载文档内容。

## 进程边界

Vue 负责展示和交互，不直接读取文件系统，也不执行 Git。路径验证、文档读写、图片落盘、仓库发现、Worktree、diff、提交、凭据和网络操作全部通过一组与 Rust handler 一一对应的 Tauri 命令。读取文档的纯命令不修改最近文件；只有明确的“打开文档”命令会产生最近文件状态。

所有命令从 Tauri 的异步 IPC 调度进入 Rust，耗时文件和 Git 操作不会占用 IPC 主处理线程。同一仓库的写操作由 Rust 仓库锁串行化；文件监听事件携带仓库根路径，前端只让对应 Worktree 会话重新读取真实磁盘版本。搜索使用可取消的代次，不占用仓库写锁，也不会把旧结果覆盖到新查询上。

Rust 核心使用 `git2/libgit2` 的内嵌 HTTPS 能力。凭据回调按仓库的统一身份读取 Windows Credential Manager 或 Android Keystore 中的条目，状态文件只保存凭据引用。

## 代码职责边界

`src-tauri/src/ipc_commands.list` 是原生命令集合的唯一清单。Rust 构建脚本据此生成 Tauri handler，`scripts/generate-bindings.mjs` 从同一清单和 Rust 序列化类型生成前端参数、返回值与调用函数；前端不手写第二份 IPC 合同。

Rust 的 `commands.rs`、`documents.rs` 和 `git.rs` 只负责模块公开面。命令适配、文档内容与资源、仓库状态、Worktree、变更、冲突和同步状态机分别位于对应子模块；路径规范化、内容范围判断和文件版本校验各自只有一个实现。Vue 的 `useWorkspace.ts` 同样只是公开面，状态、保存、文档、仓库和 Git 流程分开维护。根组件负责组合应用外壳，弹窗和覆盖层负责各自展示；展示组件与编辑器不直接依赖原生传输。

## 同步事务

同步是持久化状态机，而不是一串只存在于内存中的命令：

1. `Prepare` 把持久化变更清单与真实 Git 状态求交集，只保留 Markdown、图片和 `.marktree/config.json`，并持久化本轮路径。
2. `Commit` 从 HEAD 构造独立的临时 index，只加入本轮 Marktree 路径并创建带唯一操作标记的提交；真实 index 中用户原有的暂存项始终不被改写。
3. `Fetch` 获取 upstream。
4. `PreserveWorkingTree` 精确保留混合仓库里尚未提交的工作区与 index 状态。
5. `Rebase` 快进或变基到 upstream。
6. `RestoreWorkingTree` 在 push 前恢复保留状态，确保随后推送的只是已经验证过的仓库状态。
7. `Push` 推送当前分支。
8. `Finalize` 删除本操作创建的 stash、清除已完成代次对应的变更清单和持久化操作记录。

每一步的结果先后关系都写入 Rust 的持久化操作状态。进程在提交后退出时，恢复流程通过唯一操作标记识别已经生成的提交，不会重复提交；stash 应用使用开始/完成两阶段状态和精确树快照识别，不会重复应用。若崩溃后同一路径出现新的外部修改，恢复和中止都会停止并保留 stash，而不是覆盖新内容。中止本身也先持久化为状态机动作，重启后可以继续完成；远端已经可能成功时不再假装能够安全回滚。

发生文本、二进制或删除冲突时，libgit2 rebase 保持进行中。Marktree 把可用的祖先、本机和远端版本写入应用私有恢复区，恢复目录 ID 由操作和冲突内容确定，崩溃重试不会制造重复副本。用户选择整篇版本，或在 Windows 上确认逐段合并内容后，状态机继续 rebase、恢复工作区和 push。

## 编辑器与保存

CodeMirror 的文档字符串始终是原始 Markdown。排版由语法树装饰和小组件完成：

- 光标离开结构后隐藏标题、强调、链接等标记；
- Frontmatter、表格、任务列表、数学和 Mermaid 提供可视化；
- 光标回到结构时重新显示源码；
- 未识别扩展不解析、不改写，继续显示原文。

同一标签页的保存按修订号串行执行，后一次编辑不会被较慢的前一次写入覆盖。窗口关闭、隐藏和仓库切换会等待相关 Worktree 的保存队列刷完。保存过程直接写出 CodeMirror 字符串，所以只打开不编辑不会触发格式化；监听到外部变化后，干净标签页更新为磁盘内容，脏标签页保留用户缓冲区并显示冲突。

## 平台差异

Windows 展示仓库栏、Worktree、独立窗口、暂存区和高级 Git 面板。Android 将仓库克隆或初始化到应用私有目录，每个仓库只有一个工作副本；界面不展示 Worktree 和暂存区，只提供仓库切换、文件搜索、编辑、状态摘要和由用户明确触发的同步，不在后台周期性拉取。
