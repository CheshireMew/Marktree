# Marktree 架构

## 单一真源

用户实际选择的工作区文件夹是内容与文件操作边界，其中的 Markdown、纯文本和资源文件是内容真源。普通文件夹不需要 Git；只有工作区根目录本身可被 `Repository::open` 精确打开时，工作区才带有 Git 能力。不会向父目录发现仓库，也不会让父工作区里的嵌套仓库获得 Git 界面。前端只持有当前会话的临时编辑缓冲区；切换工作区或 Git Worktree 不会复用另一棵内容目录的标签页、保存队列或磁盘版本。

Markdown、受支持编码的纯文本和 `.marktree/config.json` 都采用版本化保存。Rust 读取时返回 SHA-256 与“文件是否不存在”，写入前精确比较调用方看到的版本和当前磁盘版本；发生外部修改、删除或重新创建时返回结构化冲突，不覆盖磁盘。新文档使用独占创建，原子写入只替换已通过版本检查的目标。图片按内容哈希命名，读取和写入都有大小上限；同名内容损坏时会修复实际文件，不能用文件名存在冒充写入成功。图片上传开始时还会记录所属文档的 SHA-256，完成发布前在工作区锁内再次核对，因此文档被移动、删除、外部改写或在同一路径重建时，资源不会误挂到另一份文档上。

本地应用状态位于 Tauri 应用数据目录，只记录：

- 最近打开的工作区与文件；
- 按内容根分隔的标签页路径、当前路径和收藏路径；
- 个人 Markdown 片段以及字体、字号、拼写检查、界面密度和侧栏宽度等纯界面偏好；
- Git 工作区对应的系统凭据条目 ID；
- Git 工作区中由 Marktree 成功创建、编辑、移动或删除、等待同步的相对路径及其代次；
- 尚未完成的工作区文件操作意图、阶段和一次性 Git 变更批次；
- 可恢复的 Git 操作阶段；
- Git 冲突的祖先、本机、远端恢复副本。

普通工作区不产生 Git 变更清单。正文没有数据库、缓存副本或其他内容镜像。路径型标签会在重新启动后通过正式文档读取入口重新打开真实文件，无法找到的路径直接退出恢复集合。应用数据目录另有有界的 JSONL 操作日志，只记录操作类型、持久化阶段、结果、时间、工作区根路径和稳定错误码，不记录正文、令牌或远端凭据；设置页读取的就是这个文件。片段和界面偏好可以留在前端本地存储，但不能承载文档内容。

## 进程边界

Vue 负责展示和交互，不直接读取文件系统，也不执行 Git。工作区打开与创建、路径验证、目录树、文档读写、图片落盘、新建、移动、回收站、系统程序打开，以及可选的 Git 状态、Worktree、diff、提交、凭据和网络操作，全部通过一组与 Rust handler 一一对应的 Tauri 命令。读取文档的纯命令不修改最近文件；只有明确的“打开文档”命令会产生最近文件状态。

所有命令都是实际的异步 Tauri IPC；文件系统、Git、压缩、状态文件、凭据和监听器建立等同步工作统一进入阻塞线程池，HTTP 设备授权保留原生异步流程，不会用 `async` 标记包住同步调用后继续占用 IPC 工作线程。同一工作区内容根的操作由 Rust 工作区锁串行化；每条入口在读取或继续操作前先恢复该根目录尚未完成的本地操作。目录树、Git 状态、分支、冲突和待恢复操作由一次 `WorkspaceViewSnapshot` 生成，文件条目标记和顶部状态使用同一份 Git 快照；完整工作区刷新也一次返回描述符和内容视图，不再由 Vue 组合多个时刻的结果。

文件监听按“内容根 + 窗口”持有，切换工作区、关闭窗口和忘记工作区都会解除对应监听。事件只发给订阅窗口并携带变化路径；前端把短时间内的事件合并成串行刷新，刷新期间到达的新事件进入下一轮，只有受影响的已打开标签需要重新读取真实磁盘版本。搜索是明确的可取消、尽力而为的时间点扫描，不伪装成持有工作区写锁的一致事务；文件在扫描中消失会被跳过。取消代次按“仓库身份 + 调用窗口”隔离，使用进程内单调编号，并在完成、失败、停止监听或忘记工作区时释放。搜索仍受单文件大小、一次搜索总读取量和总时长预算约束，返回路径、真实行列、片段、类型、文件元数据及截断统计；前端不从目录树或编辑缓冲区重造结果。命令集合从当前平台、是否已有工作区以及精确根目录是否具备 Git 能力派生。前端对任意根目录判断 Git 能力时，必须找到拥有该根的工作区，不能借用当前选中工作区的能力。

Rust 核心只在 `WorkspaceDescriptor.git` 非空时进入 `git2/libgit2`。凭据回调按工作区的稳定身份读取 Windows Credential Manager 或 Android Keystore 中的条目，状态文件只保存凭据引用。

## 代码职责边界

`src-tauri/src/ipc_commands.list` 是原生命令集合的唯一清单。Rust 构建脚本据此生成 Tauri handler，`scripts/generate-bindings.mjs` 从同一清单和 Rust 序列化类型生成前端参数、返回值与调用函数；生成器会检查每个登记函数确实是 Tauri 命令、每个真实命令都已登记、Serde 重命名与可选字段语义可解释、整数跨越 JavaScript 安全范围时有明确类型，并只输出命令和事件可达的 DTO。遇到载荷枚举、128 位整数或未支持的 Serde 形状会直接失败，不会静默生成错误合同。持久化操作、完整本地状态和凭据记录不是 IPC DTO，前端不手写第二份合同。

Rust 的 `commands.rs`、`documents.rs`、`workspace.rs` 和 `git.rs` 只负责模块公开面。命令适配、工作区生命周期、文档内容与资源、文件操作、Git 状态、Worktree、变更、冲突和同步状态机分别位于对应子模块；路径规范化、内容范围判断和文件版本校验各自只有一个实现。Vue 的 `useWorkspace.ts` 同样只是公开面，状态、保存、文档、工作区和 Git 流程分开维护。根组件负责组合应用外壳，弹窗和覆盖层负责各自展示；展示组件与编辑器不直接依赖原生传输。

`WorkspaceService` 是桌面 IPC、Android 系统分享/ZIP 导入和 `marktree-cli` 的共同应用边界。Agent CLI 与 Android 原生桥接都不直接拼接工作区内路径、写文件或登记 Git 变更，而是进入与桌面端相同的恢复、版本检查和精确变更生产者；需要一致事务视图的入口还进入同一工作区锁。应用状态和操作日志分别使用进程间文件锁；每次状态事务都重新读取磁盘上的最新有效状态，因此 GUI 与多个短生命周期 CLI 进程不会用各自的启动快照覆盖对方。Windows 工作区协调使用按精确仓库身份命名的系统互斥量，列表、读取、检查、变更查询和同步计划等只读 CLI 从第一次访问起就与桌面和写入 CLI 互斥，但不会为了读取创建状态目录或锁文件。结构化搜索保持上文定义的可取消时间点扫描，不长时间阻塞写入，并依靠原子发布、内部暂存隔离和文件消失容错保证不会读取半写文件。工作区锁按精确仓库身份排序，单工作区和双 Worktree 操作使用同一锁顺序。

个人 Markdown 片段属于本机交互设置，不是工作区文档。它只在 Vue 层保存片段名称、快捷词和用户明确录入的模板，并通过 CodeMirror 事务作用于当前选区；版本化 JSON 导入导出仍只搬运这份输入模板，不会复制、索引或恢复活动文档正文。移动工具栏与 `/快捷词` 自动补全共用这一份片段集合和同一套插入实现，内置片段只使用通用 Markdown。

## 文件工作区

目录扫描返回包含文件和目录的 `WorkspaceEntry`，前端用相对路径构建可展开目录树。`.git`、`.marktree` 和平台废纸篓永远不进入内容树；常见生成目录默认隐藏，工作区忽略规则可以补充普通目录。父工作区里的嵌套仓库按普通目录继续扫描，但跳过任意层级的 `.git`。版本化投影与内容树同源，但明确额外包含隐藏的 `.marktree/config.json`；监听同样观察这份配置，不观察被忽略、生成或内部目录。

文件重命名、移动、创建副本和删除前，前端先等待受影响文档的资源上传并刷盘脏标签页；未解决的外部修改冲突会阻止操作。Rust 再校验源和目标都位于内容根内、路径不经过符号链接且目标不存在。每次写入、导入、资源落盘、新建目录、移动、复制、回收、恢复和启用 Git 都先持久化完整操作意图，再执行文件系统效果，最后在一次状态写入中提交整批 Git 变更并清除意图。单文件数据先写入由操作 ID 唯一拥有的同目录暂存文件并同步，再进行条件发布；重启恢复只会发布哈希完整且目标版本仍符合预期的暂存文件，部分暂存会被丢弃，目标发生歧义时保留事实并拒绝猜测。`.marktree-<操作 ID>.tmp/.previous/.rejected` 等事务文件在目录树、搜索、监听和 Git 状态中统一视为内部状态。目录复制的执行计划记录全部源、目标、内容哈希和空目录；进程在复制中间或任一持久化边界退出后，下一次启动会校验已写部分并补齐缺失文件，冲突时保留事实并拒绝猜测。成功移动后，标签页、最近文件、收藏和当前选择统一迁移。Windows 删除进入系统回收站；Android 删除进入应用私有废纸篓，恢复和清空仍由 Rust 校验。

如果文件系统调用返回错误，操作层会先按已持久化意图核对真实磁盘结果：预期效果已经完整成立时按成功完成并返回可重建的结果；完全未生效时以一次失败终结；部分副本则按执行计划补齐后成功。一个操作 ID 不会同时留下成功与失败两个终态。

启用 Git 前，Rust 按同一版本化投影和忽略规则生成文件数量、总大小和忽略摘要。用户确认后初始化 `main`，把普通内容文件与 `.marktree/config.json` 一起写入完整本地基线提交，不自动配置远端。基线提交带有操作 ID；初始化或提交后退出都能识别已经完成的步骤，不会重复建库或提交。此后只有 Marktree 成功完成的路径会产生 `WorkspaceChange`；外部程序制造的无关改动不会被自动纳入。

## 同步事务

同步是持久化状态机，而不是一串只存在于内存中的命令：

1. `Prepare` 把持久化 `WorkspaceChange` 与真实 Git 状态求交集，只保留本轮精确的 `Upsert` 和 `Delete` 路径，并持久化本轮路径。
2. `Commit` 从 HEAD 构造独立的临时 index，只加入本轮工作区路径并创建带唯一操作标记的提交；真实 index 中用户原有的暂存项始终不被改写。
3. `Fetch` 获取 upstream。
4. `PreserveWorkingTree` 精确保留混合仓库里尚未提交的工作区与 index 状态。
5. `Rebase` 快进或变基到 upstream。
6. `RestoreWorkingTree` 在 push 前恢复保留状态，确保随后推送的只是已经验证过的仓库状态。
7. `Push` 推送当前分支。
8. `Finalize` 删除本操作创建的 stash、清除已完成代次对应的变更清单和持久化操作记录。

每一步的结果先后关系都写入 Rust 的持久化操作状态。进程在提交后退出时，恢复流程通过唯一操作标记识别已经生成的提交，不会重复提交；stash 应用使用开始/完成两阶段状态和精确树快照识别，不会重复应用。若崩溃后同一路径出现新的外部修改，恢复和中止都会停止并保留 stash，而不是覆盖新内容。中止本身也先持久化为状态机动作，重启后可以继续完成；远端已经可能成功时不再假装能够安全回滚。

发生文本、二进制或删除冲突时，libgit2 rebase 保持进行中。Marktree 把可用的祖先、本机和远端版本写入应用私有恢复区，恢复目录 ID 由操作和冲突内容确定，崩溃重试不会制造重复副本。用户选择整篇版本，或在 Windows 上确认逐段合并内容后，状态机继续 rebase、恢复工作区和 push。

## 编辑器与保存

Markdown 文件中，CodeMirror 的文档字符串始终是原始 Markdown，排版由语法树装饰和小组件完成：

- 光标离开结构后隐藏标题、强调、链接等标记；
- Frontmatter、表格、任务列表、数学和 Mermaid 提供可视化；
- 光标回到结构时重新显示源码；
- 未识别扩展不解析、不改写，继续显示原文。

手机工具栏、个人片段、工作区相对链接补全和“选择现有文件”都只产生普通 Markdown 字符串。层级大纲使用同一 Markdown 语法树识别真实标题，不把代码围栏中的 `#` 当成标题。面包屑和上一篇/下一篇只消费当前工作区相对路径。阅读模式暂时把当前 CodeMirror 投影改为只读并隐藏语法标记，打印只消费这个当前投影；两者都不写入 HTML 或第二份文档。

图片、PDF、音频和视频预览由 Rust 在精确工作区边界校验路径、类型和大小后，只把该文件加入当前进程的资源协议范围；Vue 使用资源 URL，音视频和 PDF 可按 Range 请求需要的真实字节，不再把整个文件编码进 IPC。粘贴图片由前端分块上传到应用私有临时文件，Rust 校验顺序、总量和最终长度后再通过统一的工作区资源写入链流式落盘。预览状态和上传临时文件都不进入工作区内容状态，其他文件直接进入原生“用系统程序打开”命令。

纯文本文件使用关闭 Markdown 语言和装饰的 CodeMirror 模式。两种编辑器都直接保存原始字符串。同一路径的并发打开请求合并成一次原生读取和一个标签页；同一标签页的保存按修订号串行执行，后一次编辑不会被较慢的前一次写入覆盖。资源上传先插入稳定占位符，用户在上传期间的后续编辑不会因上传回包而丢失；保存、关闭、移动和删除都会等待对应上传结束。窗口关闭、隐藏和工作区切换会等待相关内容根的保存队列刷完。Vue 的工作区公开面只暴露只读状态引用和命名动作，组件不能靠改写共享 `ref` 或时序回调改变领域状态。只打开不编辑不会触发格式化；监听到外部变化后，干净标签页更新为磁盘内容，脏标签页保留用户缓冲区并显示冲突。

## 平台差异

Windows 展示工作区栏和完整文件管理。普通工作区不显示任何 Git 状态，只在“更多”进入的工作区设置中提供“启用版本管理”；Git 工作区主界面只显示简单同步和简短状态，Worktree、暂存区、提交、分支与凭据位于高级 Git 面板。桌面和移动端都能从工作区设置查看最近操作记录。

Android 在应用私有目录创建普通工作区，也可以克隆或初始化 Git；每个 Git 工作区只有一个工作副本。界面不展示 Worktree 和暂存区，普通工作区提供文件管理、搜索、编辑和 ZIP 搬运，Git 工作区额外提供由用户明确触发的同步，不在后台周期性拉取。Android 废纸篓同样位于应用私有目录。

Android 原生桥接只负责接收系统 Intent、在单文件和缓存总量上限内把一次性 `content://` 输入流式复制到按次隔离的应用缓存，以及把已生成的 ZIP 交给系统分享面板。成功消费只清理对应传输目录，失败输入保留供重试；启动时按保留时间和总量预算清理分享输入与导出文件。待导入内容先进入可见选择对话框；用户明确选择工作区、目录及是否插入当前 Markdown 后，文字、Markdown、图片、一般附件和 ZIP 的分类、命名、写入及 Git 精确变更都由 Rust `WorkspaceService` 完成。图片插入当前 Markdown 时，Rust 先落盘内容哈希资源，再把普通相对 Markdown 链接交给 CodeMirror；一般附件先以原字节写入目标目录，再返回相对链接；没有选择插入时则在目标目录创建真实文件。ZIP 导出包含普通内容、空目录和 `.marktree/config.json`，排除 `.git` 与其他内部状态；导入在应用数据目录暂存并校验路径、重复项、大小和 Git 元数据，再以目录重命名提交为一个新的普通工作区。这里不提供通用 SAF，也不长期引用外部目录。
